# poly-paper

HTTP-сервис, эмулирующий торговую часть Polymarket: выставление и отмена ордеров, статусы,
сделки, баланс USDC и позиции по outcome-токенам. Рыночные данные настоящие — книги и рынки
проксируются в апстрим-шлюз (poly-gate), а исполняется всё внутри сервиса на бумажном
кошельке.

Маршруты `/clob/*` повторяют контракт poly-gate, поэтому робот переключается на сервис
сменой одного значения в конфиге, без нового кода.

## Запуск

Нужна локальная MongoDB.

```bash
pnpm install
cp config_example.yaml config.yaml   # поправить db.url и poly_gate.url
pnpm dev                             # или: pnpm build && pnpm start
```

Проверка: `curl localhost:8089/health`, документация — <http://localhost:8089/docs>
(OpenAPI-спека на `/docs/json`).

```bash
pnpm typecheck   # tsc для src и для тестов
pnpm test        # vitest: домен + e2e на in-memory Mongo и поддельном шлюзе
```

## API

Торговля — эмуляция:

| Метод | Путь |
| --- | --- |
| POST | `/clob/order` |
| DELETE | `/clob/order` |
| GET | `/clob/order/:orderID` |
| GET | `/clob/open-orders` |
| GET | `/clob/user-trades` |
| POST | `/clob/merge` |
| GET | `/clob/usdc-balance` |
| GET | `/clob/token-balance?token_id=` |

Рыночные данные — прокси в апстрим без изменения полей: `GET /clob/order-book`,
`POST /clob/order-books`, `GET /clob/markets/:conditionId`.

Служебное: `GET /health`, `GET /paper/wallet`, `GET /paper/portfolio` (mark-to-market и PnL
от стартового баланса), `POST /paper/wallet/deposit`, `POST /paper/wallet/reset`,
`GET /paper/orders`, `GET /paper/orders/:orderID/trades`, `POST /paper/orders/cancel-all`,
`GET /paper/markets`.

Ответы `/clob/order*` повторяют соглашения CLOB: суммы и цены — десятичные строки,
`createdAt` — ISO-8601. `/clob/user-trades` отдаёт уже смапленные UserTrade-строки как
poly-gate (`avgPrice`/`matchedAmount` числами, `matchTime` — epoch ms). Ответы `/paper/*` —
обычные числа и миллисекунды.

Отказ в постановке ордера (не хватило средств, цена не по тику, рынок разрешён) — это
`200` с `{"ok": false, "errorMsg": "..."}`, как и у CLOB. Ошибка валидации самого
запроса — `400`. Успешный ответ: `{ ok, orderId, status, makingAmount, takingAmount,
tradeIds, transactionsHashes }` (amounts — строки, `status` в нижнем регистре).

## Как эмулируется исполнение

1. **Мгновенное исполнение по книге.** Если ордер пересекает книгу в момент постановки, он
   исполняется по ценам книги, уровень за уровнем, в пределах видимой глубины. Остаток
   остаётся LIVE. Отключается через `paper.instant_taker_fill: false`.
2. **Исполнение стоящего ордера.** Сервис слушает публичные сделки Polymarket по WebSocket.
   Стоящий ордер исполняется, когда рынок торгует *сквозь* его цену (ниже лимита для BUY,
   выше — для SELL) объёмом не меньше остатка; филлы книжатся по цене самого ордера.
   Сделки ровно по цене лимита не считаются: в реальной очереди впереди мог стоять кто-то
   другой. Каждый ордер держит свой курсор по потоку сделок, поэтому два ордера на одном
   активе матчатся против одних и тех же событий независимо.
3. **Частичные филлы.** Ордер остаётся LIVE с растущим `size_matched` и отдельной сделкой на
   каждый филл, в MATCHED переходит только при полном исполнении — как на CLOB.
4. **Разрешение рынка.** Раз в `paper.manage_interval` сервис проверяет открытые рынки: у
   разрешённого сначала отменяются стоящие ордера (это возвращает резервы), следующим
   проходом выигрышные токены гасятся по $1 за штуку, рынок закрывается.

Резервы: BUY блокирует USDC по цене лимита, SELL — сами шеры. `/clob/usdc-balance` и
`/clob/token-balance` показывают только свободную часть, поэтому робот не может дважды
распорядиться одними деньгами.

Чего в эмуляции нет: комиссий, задержек на подтверждение, приоритета в очереди, влияния
собственного ордера на книгу.

## Интеграция с роботом

1. В конфиге робота указать `poly_gate.url: http://localhost:8089` — этого достаточно,
   чтобы и торговля, и рыночные данные шли через сервис.
2. `polymarket.api_key` и при необходимости `polymarket.maker_address` должны совпадать у
   робота и у сервиса: сервис подставляет их в `owner` / `makerAddress` ордеров и сделок.
3. `poly_gate.token` у робота должен быть непустым (его клиент падает на пустом), но сервис
   токен не проверяет.
4. `poly_gate.url` в конфиге **сервиса** — это адрес настоящего шлюза, куда проксируются
   книги и рынки. Не перепутать с пунктом 1.

## Структура

```
src/domain/      чистая логика: матчинг, арифметика денег, валидация ордера
src/storage/     репозитории Mongo, все изменения кошелька — атомарные апдейты
src/marketData/  клиент апстрим-шлюза и market WebSocket Polymarket
src/service/     сценарии: постановка/отмена ордеров, филлы, кошелёк
src/engine/      фон: тик матчинга, разрешение рынков
src/http/        Fastify, схемы zod, Swagger
```
